|---|---|---|

## 스토어 아이콘

앱에 들어 있는 **어댑티브 아이콘을 그대로** 내보낸 것이다(새로 디자인하지 않았다).
원본은 `android/app/src/main/res/` 의 `values/colors.xml` + `drawable/ic_launcher_foreground.xml` 이고,
`make_store_icon.py` 가 그 좌표를 재현한다. **아이콘을 바꾸면 스크립트의 상수도 같이 고쳐야 한다.**

```bash
/tmp/imgvenv/bin/python docs/store-assets/make_store_icon.py
```

두 가지를 맞췄다.

- **여백**: 어댑티브 아이콘은 108dp 중 **가운데 72dp 만** 런처에 보인다(나머지는 마스크로 잘린다).
  스토어 아이콘은 잘리지 않으므로, 런처와 같은 크기로 보이려면 가운데 72/108 을 잘라 512 로 키워야 한다.
  108 을 그대로 쓰면 런처보다 작아 보인다.
- **비트 깊이**: Play 는 "32비트 PNG"를 요구하면서 투명은 금지한다. 알파 채널을 두되 전면을 255 로 채웠다
  (24비트 RGB 로 저장하면 규격에서 걸릴 수 있다). 스크립트가 저장 후 이 두 가지를 단언으로 검사한다.

둥근 모서리·그림자는 넣지 않았다 — 구글이 알아서 처리한다.

### 품질 판단 (2026-09-21)

512·192·96px 에서는 체크가 또렷하고 가장자리도 깨끗하다. **48px(스토어 목록 크기)에서는 읽히기는 하지만
약하다** — 흰 본체가 화면을 지배하고 체크가 작아서, 멀리서 보면 "흰 막대"로 읽힌다. 32px 에서는 거의 뭉갠다.

**내부·클로즈드 테스트에는 이대로 써도 된다**(규격 위반이 아니라 심사에서 거부되지 않는다).
다만 프로덕션 전에는 **사람이 손보는 편이 낫다.** 체크를 키우거나 본체를 줄여 대비를 높이는 정도면 충분하다.
지금 도안은 "흰 바탕에 파란 체크"라 흔하기도 하다.

## 왜 원본을 그대로 안 쓰나

Pixel 6 캡처는 1080×2400 = **2.22:1** 인데, Play 스크린샷은 **장변이 단변의 2배를 넘으면 안 된다.**
그대로 올리면 거부될 수 있어서 9:16 캔버스에 얹어 1080×1920 으로 맞췄다. 겸사겸사 문구도 넣었다.

## 문구 바꾸기

`make_store_assets.py` 상단 `SHOTS` 의 caption 한 줄만 고치고 다시 실행하면 된다. `\n` 으로 줄바꿈.

```bash
python3 -m venv /tmp/imgvenv && /tmp/imgvenv/bin/pip install Pillow
/tmp/imgvenv/bin/python docs/store-assets/make_store_assets.py docs/store-assets/raw
```

Pillow 는 이 저장소의 의존성이 아니다. **저장소나 시스템에 설치하지 말고 임시 venv 를 쓴다.**

## 화면을 다시 찍어야 한다면

`raw/` 를 지우고 에뮬레이터에서 다시 캡처한다(`adb exec-out screencap -p > raw/raw1_feedback.png`).
어떤 화면을 어떻게 띄웠는지는 [planning-and-dev-log.md](../planning-and-dev-log.md) 16절에 적어 두었다.
키보드 화면을 찍으려면 TypeRight 를 기본 키보드로 바꿔야 하는데,
**에뮬레이터는 다른 작업과 공용이므로 끝나면 Gboard 로 되돌린다.**

## 주의: 실제 동작만 담는다

- 타사 앱(카카오톡 등) UI 를 흉내 낸 가짜 화면은 만들지 않는다 — 상표 문제이고, 실제 동작이 아닌 것을
  스토어에 올리는 셈이다. 입력 화면은 앱 안의 '테스트 입력' 칸을 쓴다.
- 6번(`입력한 문장은 기기 밖으로 나가지 않아요`)은 [privacy-claims.md](../privacy-claims.md) 로 뒷받침되는
  사실이다. **AI 를 되살리면 이 문구와 스크린샷을 먼저 내려야 한다.**
