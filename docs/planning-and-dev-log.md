## 2. 기획 변천사

### 2.1 기획서 V2 (TypeRight, 구 KorGrammar)
- 하이브리드 교정: 온디바이스 규칙(1차) + 클라우드 AI(2차)
- Android(Kotlin) + iOS(Swift) 동시 개발, 백엔드 Node(Fastify) 또는 Python(FastAPI)
- LLM: GPT-4o-mini **또는** Claude Haiku
- 기능: QWERTY·천지인, 상단 교정 칩, 보안 필드 차단, 300ms 디바운스, PII 마스킹, **톤 변환(격식/친근/비즈니스)**, 단축어, 구독
- → 이 기준으로 첫 구현 착수 (Fastify + Claude Haiku 4.5)

### 2.2 기획서 V4 (위트 훈수 · 강제성 UX · 1인 개발 서버리스)
- 핵심 가치 전환: 교정 → **유쾌한 훈수 + 게임화된 강제성**
- 피드백 3모드 도입, 경찰 모드(사이렌 햅틱 + 교정 전 스페이스바 차단)
- 백엔드: Vercel Serverless + Supabase, LLM은 GPT-4o-mini 명시
- 응답 스키마 변경: `corrected_text`, `wit_feedback`, `suggestions[].type` 추가
- BM: 무료 5회/일 · AdMob 보상형 광고 · PRO 구독
- 3주 마일스톤: 1주 클라이언트 코어 → 2주 백엔드·AI → 3주 BM·출시

### 2.3 맞춤법 참고 자료 (34개 항목)
가리키다/가르키다, 그러므로/그럼으로, 깍두기, 깨끗이, 끼어들기, 나는/날으는, 낢, 너머/넘어, 널따랗다, 넙죽, 더욱이, 되/돼, 띠다/띄다, 머리말, 멋쩍다, 며칠, 받히다/받치다, 반드시/반듯이, 부숴뜨리다, 부치다/붙이다, 사귀어, 성공률, 숟가락, 스포츠난, 썩이다, 아무튼, 안/않, 알맞은, 어떡해/어떻게, 이따가/있다가, 있음, 졸업연도, 할게, 오랫동안/오랜만 → 규칙 파일에 반영(4장).

### 2.4 기술 스택 변경 (Plan B)
- 백엔드를 **Python FastAPI**로 확정 (Pydantic 검증, async/await, AI 프롬프트 처리 생산성)
- 호스팅 후보: Vercel 또는 Render

### 2.5 MVP 범위 축소
- **Android(Kotlin) + FastAPI + Supabase**로 먼저 출시해 시장 검증
- 이유: iOS 개발 부담 제거, Apple 개발자 계정($99/년) 대신 Google Play 등록비 $25만으로 출시 가능, 2주 내 출시 목표
- Supabase 역할: 유저별 일일 AI 사용 횟수 관리 + **단축어 동기화**

## 4. 맞춤법 규칙 설계

### 4.1 원칙
- **단일 원본**: `shared/korean-rules.json` 하나를 서버와 Android가 함께 사용 (서버는 동기화 복사본을 커밋, 드리프트 시 테스트 실패)
- **크로스플랫폼 골든 테스트**: `shared/rule-golden-cases.json` — 교정 29 · 피드백 6 · 유형 4 케이스, 서버·Android 결과가 완전히 일치해야 함
- 현재 규모: 사전 130개 + 정규식 패턴 11개, 매운맛 전용 멘트 48개

### 4.2 규칙화 vs AI 위임 기준
| 유형 | 처리 | 예 |
|---|---|---|
| 문맥과 무관하게 항상 틀린 표기 | 규칙 사전 | 몇일, 됬, 깍뚜기, 더우기, 아뭏든, 있슴, 알맞는, 성공율, 날으는, 머릿말, 사겨, 졸업년도, 오랜동안, `~히→~이` |
| 문맥 의존이지만 확실한 연어 | 규칙(연어 단위) | 미소를 띄→띠, 눈에 띠→띄, 우표를 부치→붙이, 소포를 붙이→부치, 있다가 보자→이따가 보자 |
| 문맥 판단 필요 | AI 프롬프트 집중 점검 목록 | 너머/넘어, 반드시/반듯이, 받히다/받치다, 그러므로/그럼으로(써), 비추다/비치다, 낢/남 |
| 문장 끝 형태 | 패턴 | "그래도 되?" → 돼, "학교에 않 갈거니" → 안 |

- 경찰 모드는 오탐 시 입력을 막아버리므로 **오탐 위험이 있는 규칙은 넣지 않는 것**을 기준으로 삼음
- 참고 자료 16번은 "몇 일(O)"로 적혀 있으나 국립국어원 기준 표준은 '며칠'만이므로 `몇 일 → 며칠` 규칙 유지

### 4.3 엔진 알고리즘 (3개 플랫폼 공통)
1. 사전 항목의 모든 등장 위치 검색 → 2. 패턴을 원문 전체에 매치, `$0~$9`는 직접 치환(매치 문자열에 정규식 재적용 금지 — lookaround 문맥 손실) → 3. **no-op 후보는 선택 전에 제거** → 4. (offset↑, length↓) 안정 정렬 후 겹치지 않는 것만 채택
- 정규식은 공통 문법만 허용, **`\b \s \d \w` 축약 클래스 금지**(엔진별 유니코드 범위 차이) — 백엔드 테스트가 강제
- 모든 offset은 **UTF-16 단위** (Python은 코드포인트 기준이라 API 경계에서 변환, 이모지 골든 케이스로 고정)

### 4.4 피드백 생성
- 첫 번째 교정 기준. 매운맛은 규칙별 `wit` 멘트 우선, 없으면 모드별 템플릿
- 예: 어의 → "어의는 조선시대 궁궐 의사입니다. '어처구니'가 없으신 거죠? 🩺"
- 경찰: "🚨 맞춤법 위반 적발! '어의' → '어이' 교정 전까지 통과 불가!" / 선생님: "✏️ '어의' → '어이' : (문법 설명)"

## 5. 개발 측 결정 사항 (기획서에 명시되지 않아 정한 것)

### 5.1 제품 정책
| 항목 | 결정 | 이유 |
|---|---|---|
| AI 쿼터 차감 | AI가 오류를 찾아 훈수를 전달했을 때만 1회 차감 | 하루 5회가 오류 없는 문장에 소진되지 않도록 |
| 경찰 모드 무료/PRO | 무료 = 햅틱 경고만, PRO = 스페이스바·엔터·`. ! ?` 차단 | V4 "경찰 모드 풀버전 = PRO" |
| 경찰 모드 탈출구 | '무시' 칩 항상 제공 (키: 절대 위치 + 원문 단어, 문장 시작 이동 시 초기화) | 오탐 시 입력 불능 방지 |
| PRO "무제한" | 서버 fair-use 상한 300회/일 | 비용 폭주·남용 방지 |
| 광고 보상 | 1회 +3, 하루 최대 5회 시청, 당일 소멸 | 남용 방지 |
| 광고 노출 위치 | 키보드 안이 아닌 호스트 앱(`typeright://reward` 딥링크) | IME 내 전면 광고 부적합, iOS 앱 확장은 AdMob 미지원 |
| AI 호출 시점 | 문장 끝(`. ! ?` 줄바꿈) + 쿼터 있음 + 직전 요청과 텍스트 다를 때 | 비용·쿼터 절약 |
| 단축어 | 편집·동기화는 PRO 전용, 로컬이 원본(오프라인 동작) | V4 BM |

### 5.2 기술·보안
| 항목 | 결정 | 이유 |
|---|---|---|
| 인증 | Supabase 익명 로그인 JWT, 서버에서 로컬 검증(JWKS / 레거시 HS256) | 가입 없이 사용자 식별 |
| 요청 body `user_id` | V4 호환용으로 받되 **무시**, JWT `sub` 사용 | 위조로 타인 쿼터·PRO 도용 방지 |
| 개인정보 | AI 호출 전 주민번호·카드·전화·이메일·계좌 마스킹, 서버 로그에 입력 텍스트 미기록, 캐시 키도 마스킹본 | 기획서 PII 요구사항 |
| 규칙 vs AI 충돌 | 같은 구간은 규칙 우선, AI offset은 원문에서 재탐색해 검증(환각 구간 제거) | LLM offset 부정확 |
| AI 실패 | 재시도 없음·6초 타임아웃, 실패 시 규칙 결과로 강등(`ai_status: unavailable`) | 키보드는 지연이 치명적 |
| 광고 보상 검증 | AdMob SSV ECDSA 서명 검증 + `transaction_id` 멱등 | 클라이언트 보상 위조 방지 |
| 쿼터 저장 | Postgres 함수로 원자적 차감, KST 자정 리셋, 클라이언트 RPC 권한 회수 | 동시성·위조 방지 |
| 응답 폐기(stale guard) | 검사한 문장이 같은 위치에 그대로 있으면 유효, 뒤에 이어 친 입력은 무관 | 스페이스 한 번에 AI 결과가 버려지는 문제 해결 |
| 호스팅 | Vercel(`icn1`) | Render 무료 플랜은 유휴 슬립 → 콜드스타트 수십 초 |
| 로컬 dev 포트 | 8790 | 8787은 이 개발 머신에서 다른 프로세스가 사용 중 |
| 로컬 dev 인증 | `ALLOW_INSECURE_DEV_AUTH=true` + `X-Dev-User-Id` 헤더, 인메모리 쿼터 (production에서는 부팅 거부) | Supabase 없이 개발 |

## 6. 기획 자료에서 바로잡은 내용

| 기획/가이드 내용 | 실제 | 반영 |
|---|---|---|

| V4 응답 예시 `offset: 5, length: 2, "어의"` | "오늘 진짜 어의가 없네"에서 5번은 공백, '어의'는 6번 | 계약서 예시 수정(6) |

| V4 시스템 프롬프트 "JSON 스키마를 지켜라" | 프롬프트 지시만으로는 형식 보장이 안 됨 | OpenAI Structured Outputs(Pydantic 스키마 강제) + 프롬프트 인젝션 방어 문구 |
| 맞춤법 자료 "몇 일(O)" | 국립국어원 기준 '며칠'만 표준 | 기존 규칙 유지 |

## 7. 전체 동작 흐름

```
[키 입력] → [보안 필드?] ─YES→ 캡처·검사·네트워크·경찰 차단 전면 중단 (보안 키패드)
               │NO
               ▼
[300ms 디바운스 / 스페이스 즉시] → [온디바이스 규칙 검사] → 교정 칩 + 모드별 피드백
               │
               ├─ 경찰 모드(PRO) & 미교정 오류 → 사이렌 햅틱 + 스페이스/엔터/문장부호 차단
               │
[문장 끝 . ! ? 줄바꿈] + 네트워크 + (PRO 또는 잔여 쿼터) + 텍스트 변경
               ▼
[POST /v1/grammar-check] → JWT 검증 → 규칙 검사 → 쿼터 확인 → PII 마스킹 → GPT-4o-mini
               ▼
[병합: 규칙 우선 + AI 구간 원문 재검증] → corrected_text · wit_feedback · suggestions · quota
               ▼
[stale guard 통과 시 렌더링] ─ quota_exceeded → "광고 보고 3회 충전" 칩 → 호스트 앱
               ▼
[교정 칩 탭] → InputConnection으로 원문 교체, 경찰 차단 해제
```

API: `POST /v1/grammar-check`, `GET /v1/me`, `GET /v1/ads/admob-ssv`(AdMob 전용), `GET /health` — 상세는 [api-contract.md](api-contract.md)

## 8. 구현 현황 (2026-09-11 기준)

### 8.1 백엔드 (`backend/`, Python FastAPI)
- 규칙 엔진, 피드백 생성, UTF-16 변환, PII 마스킹, OpenAI 연동, 쿼터(인메모리/Supabase), JWT 인증, AdMob SSV, Vercel 엔트리
- **pytest 103개 통과** (OpenAI는 HTTP 모킹으로 성공·거절·잘림·5xx·429·연결 실패 검증)
- 실제 서버 기동 후 curl로 V4 응답 형태 확인
- 변천: Fastify(TS) + Claude Haiku → Fastify(TS) + OpenAI → **FastAPI + OpenAI** (TS 구현 폐기)

### 8.2 Supabase (`backend/supabase/migrations/`)
- `entitlements`(PRO), `ai_usage`(일일 사용량·보너스), `ad_rewards`(광고 원장), `shortcuts`(단축어, RLS)
- Postgres 18(PGlite)에서 적용 + 검증: 쿼터 상한, 보너스 사용, 광고 멱등·일일 상한, PRO 만료, 클라이언트의 쿼터 RPC 차단, 단축어 RLS(PRO만 쓰기, 사용자 간 격리)
- 실제 Supabase 프로젝트 적용은 미확인

### 8.3 Android (`android/`)
- `app/`(호스트 앱): 온보딩, 설정(AI on/off, 피드백 모드, 자판, 계정·쿼터), 단축어(PRO 게이트 + 동기화), 보상 화면(광고 스텁), PRO 화면(결제 스텁)
- `keyboard/`(IME): 두벌식·영문·기호·천지인, 한글 조합기 2종, 고정 높이 제안 바(교정·무시·단축어·충전 칩), 모드별 피드백(말풍선/사이렌+차단/팁 카드), 보안 필드 처리, 디바운스, stale guard, Supabase 익명 세션, API 클라이언트
- **단위 테스트 107개(15개 클래스) 통과, 디버그 APK 빌드 성공** — 골든 케이스 전체 포함
- 버전: AGP 9.4.0 · Kotlin 2.3.21 · Compose BOM 2026.06.01 · Gradle wrapper 9.7.1

### 8.4 iOS (`ios/`) — 보류
- Core 패키지 일부만 존재, 빌드 불가, 미검증. 재개 방법은 `ios/README.md`

### 8.5 코드 리뷰 결과
- 채택 1건: `AI_ENABLED=true`인데 API 키가 없으면 모든 엔드포인트가 500 → 키가 있을 때만 AI 활성화하도록 수정 + 테스트
- 기각 4건 (근거 확인): 쿼터 UPDATE 경합(Postgres가 행 잠금 후 조건 재평가), ES256/RS256 혼용(둘 다 비대칭 키 + `kid`로 키 선택), 6초 타임아웃(15초 한도 내 여유), AI offset 재검증(정확 일치 검색이라 불필요)
- Android 에이전트 제안 반영: `$0` 치환 규칙 통일, 정규식 축약 클래스 금지, 무시 목록 키 정의
