## 2. 기획 변천사

### 2.1 기획서 V2 (TypeRight, 구 KorGrammar)
- 하이브리드 교정: 온디바이스 규칙(1차) + 클라우드 AI(2차)
- Android(Kotlin) + iOS(Swift) 동시 개발, 백엔드 Node(Fastify) 또는 Python(FastAPI)
- LLM: GPT-4o-mini **또는** Claude Haiku
- 기능: QWERTY·천지인, 상단 교정 칩, 보안 필드 차단, 300ms 디바운스, PII 마스킹, **톤 변환(격식/친근/비즈니스)**, 단축어, 구독
- → 이 기준으로 첫 구현 착수 (Fastify + Claude Haiku 4.5)

### 2.2 기획서 V4 (위트 훈수 · 강제성 UX · 1인 개발 서버리스)
- 핵심 가치 전환: 교정 → **유쾌한 훈수 + 게임화된 강제성**
- 피드백 3모드 도입, 경찰 모드(사이렌 햅틱 + 교정 전 스페이스바 차단)
- 백엔드: Vercel Serverless + Supabase, LLM은 GPT-4o-mini 명시
- 응답 스키마 변경: `corrected_text`, `wit_feedback`, `suggestions[].type` 추가
- BM: 무료 5회/일 · AdMob 보상형 광고 · PRO 구독
- 3주 마일스톤: 1주 클라이언트 코어 → 2주 백엔드·AI → 3주 BM·출시

### 2.3 맞춤법 참고 자료 (34개 항목)
가리키다/가르키다, 그러므로/그럼으로, 깍두기, 깨끗이, 끼어들기, 나는/날으는, 낢, 너머/넘어, 널따랗다, 넙죽, 더욱이, 되/돼, 띠다/띄다, 머리말, 멋쩍다, 며칠, 받히다/받치다, 반드시/반듯이, 부숴뜨리다, 부치다/붙이다, 사귀어, 성공률, 숟가락, 스포츠난, 썩이다, 아무튼, 안/않, 알맞은, 어떡해/어떻게, 이따가/있다가, 있음, 졸업연도, 할게, 오랫동안/오랜만 → 규칙 파일에 반영(4장).

### 2.4 기술 스택 변경 (Plan B)
- 백엔드를 **Python FastAPI**로 확정 (Pydantic 검증, async/await, AI 프롬프트 처리 생산성)
- 호스팅 후보: Vercel 또는 Render

### 2.5 MVP 범위 축소
- **Android(Kotlin) + FastAPI + Supabase**로 먼저 출시해 시장 검증
- 이유: iOS 개발 부담 제거, Apple 개발자 계정($99/년) 대신 Google Play 등록비 $25만으로 출시 가능, 2주 내 출시 목표
- Supabase 역할: 유저별 일일 AI 사용 횟수 관리 + **단축어 동기화**

## 4. 맞춤법 규칙 설계

### 4.1 원칙
- **단일 원본**: `shared/korean-rules.json` 하나를 서버와 Android가 함께 사용 (서버는 동기화 복사본을 커밋, 드리프트 시 테스트 실패)
- **크로스플랫폼 골든 테스트**: `shared/rule-golden-cases.json` — 교정 29 · 피드백 6 · 유형 4 케이스, 서버·Android 결과가 완전히 일치해야 함
- 현재 규모: 사전 130개 + 정규식 패턴 11개, 매운맛 전용 멘트 48개

### 4.2 규칙화 vs AI 위임 기준
| 유형 | 처리 | 예 |
|---|---|---|
| 문맥과 무관하게 항상 틀린 표기 | 규칙 사전 | 몇일, 됬, 깍뚜기, 더우기, 아뭏든, 있슴, 알맞는, 성공율, 날으는, 머릿말, 사겨, 졸업년도, 오랜동안, `~히→~이` |
| 문맥 의존이지만 확실한 연어 | 규칙(연어 단위) | 미소를 띄→띠, 눈에 띠→띄, 우표를 부치→붙이, 소포를 붙이→부치, 있다가 보자→이따가 보자 |
| 문맥 판단 필요 | AI 프롬프트 집중 점검 목록 | 너머/넘어, 반드시/반듯이, 받히다/받치다, 그러므로/그럼으로(써), 비추다/비치다, 낢/남 |
| 문장 끝 형태 | 패턴 | "그래도 되?" → 돼, "학교에 않 갈거니" → 안 |

- 경찰 모드는 오탐 시 입력을 막아버리므로 **오탐 위험이 있는 규칙은 넣지 않는 것**을 기준으로 삼음
- 참고 자료 16번은 "몇 일(O)"로 적혀 있으나 국립국어원 기준 표준은 '며칠'만이므로 `몇 일 → 며칠` 규칙 유지

### 4.3 엔진 알고리즘 (3개 플랫폼 공통)
1. 사전 항목의 모든 등장 위치 검색 → 2. 패턴을 원문 전체에 매치, `$0~$9`는 직접 치환(매치 문자열에 정규식 재적용 금지 — lookaround 문맥 손실) → 3. **no-op 후보는 선택 전에 제거** → 4. (offset↑, length↓) 안정 정렬 후 겹치지 않는 것만 채택
- 정규식은 공통 문법만 허용, **`\b \s \d \w` 축약 클래스 금지**(엔진별 유니코드 범위 차이) — 백엔드 테스트가 강제
- 모든 offset은 **UTF-16 단위** (Python은 코드포인트 기준이라 API 경계에서 변환, 이모지 골든 케이스로 고정)

### 4.4 피드백 생성
- 첫 번째 교정 기준. 매운맛은 규칙별 `wit` 멘트 우선, 없으면 모드별 템플릿
- 예: 어의 → "어의는 조선시대 궁궐 의사입니다. '어처구니'가 없으신 거죠? 🩺"
- 경찰: "🚨 맞춤법 위반 적발! '어의' → '어이' 교정 전까지 통과 불가!" / 선생님: "✏️ '어의' → '어이' : (문법 설명)"

## 5. 개발 측 결정 사항 (기획서에 명시되지 않아 정한 것)

### 5.1 제품 정책
| 항목 | 결정 | 이유 |
|---|---|---|
| AI 쿼터 차감 | AI가 오류를 찾아 훈수를 전달했을 때만 1회 차감 | 하루 5회가 오류 없는 문장에 소진되지 않도록 |
| 경찰 모드 무료/PRO | 무료 = 햅틱 경고만, PRO = 스페이스바·엔터·`. ! ?` 차단 | V4 "경찰 모드 풀버전 = PRO" |
| 경찰 모드 탈출구 | '무시' 칩 항상 제공 (키: 절대 위치 + 원문 단어, 문장 시작 이동 시 초기화) | 오탐 시 입력 불능 방지 |
| PRO "무제한" | 서버 fair-use 상한 300회/일 | 비용 폭주·남용 방지 |
| 광고 보상 | 1회 +3, 하루 최대 5회 시청, 당일 소멸 | 남용 방지 |
| 광고 노출 위치 | 키보드 안이 아닌 호스트 앱(`typeright://reward` 딥링크) | IME 내 전면 광고 부적합, iOS 앱 확장은 AdMob 미지원 |
| AI 호출 시점 | 문장 끝(`. ! ?` 줄바꿈) + 쿼터 있음 + 직전 요청과 텍스트 다를 때 | 비용·쿼터 절약 |
| 단축어 | 편집·동기화는 PRO 전용, 로컬이 원본(오프라인 동작) | V4 BM |

### 5.2 기술·보안
| 항목 | 결정 | 이유 |
|---|---|---|
| 인증 | Supabase 익명 로그인 JWT, 서버에서 로컬 검증(JWKS / 레거시 HS256) | 가입 없이 사용자 식별 |
| 요청 body `user_id` | V4 호환용으로 받되 **무시**, JWT `sub` 사용 | 위조로 타인 쿼터·PRO 도용 방지 |
| 개인정보 | AI 호출 전 주민번호·카드·전화·이메일·계좌 마스킹, 서버 로그에 입력 텍스트 미기록, 캐시 키도 마스킹본 | 기획서 PII 요구사항 |
| 규칙 vs AI 충돌 | 같은 구간은 규칙 우선, AI offset은 원문에서 재탐색해 검증(환각 구간 제거) | LLM offset 부정확 |
| AI 실패 | 재시도 없음·6초 타임아웃, 실패 시 규칙 결과로 강등(`ai_status: unavailable`) | 키보드는 지연이 치명적 |
| 광고 보상 검증 | AdMob SSV ECDSA 서명 검증 + `transaction_id` 멱등 | 클라이언트 보상 위조 방지 |
| 쿼터 저장 | Postgres 함수로 원자적 차감, KST 자정 리셋, 클라이언트 RPC 권한 회수 | 동시성·위조 방지 |
| 응답 폐기(stale guard) | 검사한 문장이 같은 위치에 그대로 있으면 유효, 뒤에 이어 친 입력은 무관 | 스페이스 한 번에 AI 결과가 버려지는 문제 해결 |
| 호스팅 | Vercel(`icn1`) | Render 무료 플랜은 유휴 슬립 → 콜드스타트 수십 초 |
| 로컬 dev 포트 | 8790 | 8787은 이 개발 머신에서 다른 프로세스가 사용 중 |
| 로컬 dev 인증 | `ALLOW_INSECURE_DEV_AUTH=true` + `X-Dev-User-Id` 헤더, 인메모리 쿼터 (production에서는 부팅 거부) | Supabase 없이 개발 |

## 6. 기획 자료에서 바로잡은 내용

| 기획/가이드 내용 | 실제 | 반영 |
|---|---|---|

| V4 시스템 프롬프트 "JSON 스키마를 지켜라" | 프롬프트 지시만으로는 형식 보장이 안 됨 | OpenAI Structured Outputs(Pydantic 스키마 강제) + 프롬프트 인젝션 방어 문구 |
| 맞춤법 자료 "몇 일(O)" | 국립국어원 기준 '며칠'만 표준 | 기존 규칙 유지 |

## 7. 전체 동작 흐름

```
[키 입력] → [보안 필드?] ─YES→ 캡처·검사·네트워크·경찰 차단 전면 중단 (보안 키패드)
               │NO
               ▼
[300ms 디바운스 / 스페이스 즉시] → [온디바이스 규칙 검사] → 교정 칩 + 모드별 피드백
               │
               ├─ 경찰 모드(PRO) & 미교정 오류 → 사이렌 햅틱 + 스페이스/엔터/문장부호 차단
               │
[문장 끝 . ! ? 줄바꿈] + 네트워크 + (PRO 또는 잔여 쿼터) + 텍스트 변경
               ▼
[POST /v1/grammar-check] → JWT 검증 → 규칙 검사 → 쿼터 확인 → PII 마스킹 → GPT-4o-mini
               ▼
[병합: 규칙 우선 + AI 구간 원문 재검증] → corrected_text · wit_feedback · suggestions · quota
               ▼
[stale guard 통과 시 렌더링] ─ quota_exceeded → "광고 보고 3회 충전" 칩 → 호스트 앱
               ▼
[교정 칩 탭] → InputConnection으로 원문 교체, 경찰 차단 해제
```

API: `POST /v1/grammar-check`, `GET /v1/me`, `GET /v1/ads/admob-ssv`(AdMob 전용), `GET /health` — 상세는 [api-contract.md](api-contract.md)

## 8. 구현 현황 (2026-09-11 기준)

### 8.1 백엔드 (`backend/`, Python FastAPI)
- 규칙 엔진, 피드백 생성, UTF-16 변환, PII 마스킹, OpenAI 연동, 쿼터(인메모리/Supabase), JWT 인증, AdMob SSV, Vercel 엔트리
- **pytest 103개 통과** (OpenAI는 HTTP 모킹으로 성공·거절·잘림·5xx·429·연결 실패 검증)
- 실제 서버 기동 후 curl로 V4 응답 형태 확인
- 변천: Fastify(TS) + Claude Haiku → Fastify(TS) + OpenAI → **FastAPI + OpenAI** (TS 구현 폐기)

### 8.2 Supabase (`backend/supabase/migrations/`)
- `entitlements`(PRO), `ai_usage`(일일 사용량·보너스), `ad_rewards`(광고 원장), `shortcuts`(단축어, RLS)
- Postgres 18(PGlite)에서 적용 + 검증: 쿼터 상한, 보너스 사용, 광고 멱등·일일 상한, PRO 만료, 클라이언트의 쿼터 RPC 차단, 단축어 RLS(PRO만 쓰기, 사용자 간 격리)
- 실제 Supabase 프로젝트 적용은 미확인

### 8.3 Android (`android/`)
- `app/`(호스트 앱): 온보딩, 설정(AI on/off, 피드백 모드, 자판, 계정·쿼터), 단축어(PRO 게이트 + 동기화), 보상 화면(광고 스텁), PRO 화면(결제 스텁)

| 기획자 제안 | 결론 | 내용 |
|---|---|---|
| ① AdMob SSV 서버 검증 | **이미 구현** | AdMob 서버 콜백만 ECDSA 서명 검증 후 적립, transaction_id 멱등. 클라이언트 "시청 완료" 요청으로 충전하는 경로 자체가 없음 → 매크로 연타 불가 |
| ② 입력 150자 제한 | **반영** | 150자 초과는 AI 없이 규칙 교정만(`ai_status: "skipped"`). 자르지 않음(문장 중간 절단 시 교정 품질 저하) |
| ③ 룰로 "오류 없음 확실" 문장은 AI 생략 | **변형 반영** | 규칙 엔진은 아는 오류만 잡으므로 "규칙에 안 걸림 = 오류 없음"이 성립하지 않음 → 그대로 하면 AI가 문맥 오류(되/돼, 반드시/반듯이 등)를 영영 못 잡음. 대신 **한글 음절 2개 미만(ㅋㅋㅋ·숫자·영문·이모지)은 AI 생략** |
| ④ max_tokens=150 | **변형 반영: 400** | 기존 응답 JSON에 원문+교정문이 들어가 150자 문장이면 그것만으로 150토큰 초과 → 잘린 JSON은 과금되고 결과는 버려짐. **AI 출력에서 원문·교정문을 제거**(서버가 계산)해 출력 비용 약 절반으로 줄이고, 상한 400·제안 최대 5개 |
| 프롬프트 인젝션("500자 소설") | **이미 방어 + 보강** | 구조화 출력이라 스키마 밖 자유 텍스트 불가, 입력은 데이터 취급 지시. 추가로 훈수 멘트 120자 절단 |
| 광고 +3 → +5 상향 | **기획 결정 대기** | `AD_REWARD_AMOUNT` 환경변수 한 줄로 변경 가능 |
| (개발 추가) 무료 AI 무한 호출 구멍 | **반영** | "오류 있을 때만 차감" 정책 때문에 맞는 문장만 반복 전송하면 AI 무한 무료 호출 가능 → **하루 AI 호출 시도 상한** 무료 60 / PRO 1000 (`ai_status: "rate_limited"`, 광고로 해제 안 됨) |

반영 결과 (2026-09-11):
- 백엔드: 예산 가드 + 호출 대상 제한 + 호출 시도 상한 + 출력 축소 — pytest 128개 통과, 마이그레이션 4개 SQL 검증

### 11.1 개발 측 상업성 판단 (요약)

- 기타 리스크: 멘트 반복으로 인한 신선도 하락, 경찰 모드 차단의 이탈 유발, 입력 텍스트 서버 전송에 대한 불신, 바이럴 타깃(10~20대)과 결제 타깃(직장인) 불일치
- 대략 추정: MAU 1만 × 구독 전환 2% + 광고 → 월 100~170만 원 수준 (가정 다수). 의미 있는 수익엔 MAU 5만+ 필요
- 핵심 지표 제안: 설치 수가 아닌 **기본 키보드 유지율 + D7/D30 리텐션**, 중단/피벗 기준 사전 설정

### 12.1 키보드 기본기 (리텐션 벽)
11.1에서 "가장 큰 벽은 기능이 아니라 키보드 교체 장벽"이라고 적어 놓고, 정작 매일 쓰는 키보드의 기본 요구사항이
비어 있었다. 이번에 채운 것:

| 항목 | 내용 |
|---|---|
| 이모지 패널 | 8개 카테고리 + 최근 사용 24개(MRU, DataStore 영속). 하단 바에 `가/A`·`⌫`(연타 반복)을 둬서 패널을 벗어나지 않고 오타 수정 가능. 키 그리드와 같은 높이(216dp)라 열고 닫을 때 키보드가 튀지 않음 |
| 이모지 범위 | **minSdk 26(Android 8) = Emoji 5.0까지만 렌더**되므로 그 이후 추가분은 제외. Emoji 11.0+ 코드포인트가 섞이면 실패하는 테스트로 고정(🥳·🥵·🧂·🧩이 이 테스트에 걸려 교체됨) |
| 이모지 진입 | 하단 행 전용 😊 키(스페이스바 weight 4→3). 천지인은 4열이라 `.,?!` 키 롱프레스 |
| 키 진동/소리 | 진동은 원래 항상 켜져 있었고 **끌 수가 없었음** → 설정 토글 추가(기본 켬). 키 소리는 신규(기본 끔, 시스템 '터치 사운드'가 꺼져 있으면 켜도 안 남) |
| 숫자 롱프레스 | 상단 자·모/알파벳 행 롱프레스로 1~0. **주의: 롱프레스가 붙은 키는 터치다운이 아니라 릴리즈에 입력된다**(기존 최저지연 경로에서 벗어남). 주류 키보드와 같은 동작이지만 타자감 확인 시 이 부분을 같이 봐야 함 |

### 12.2 수익 경로 — 스텁 → 실제 구현
`StubSubscriptionRepository`/`StubRewardedAdProvider` 둘 다 `isAvailable = false`라 **결제도 광고 충전도 동작하지
않는 상태**였다.

**구독 (Play Billing 8.0.0 + 서버 영수증 검증)**
- `POST /v1/billing/play/verify`: 클라이언트가 보낸 구매 토큰을 `purchases.subscriptionsv2.get`으로 Google에 확인하고,
  `ACTIVE`/`IN_GRACE_PERIOD`일 때만 `entitlements`에 PRO를 넣는다. 변조 APK가 스스로 PRO를 켤 수 없다.
- 미확인 구매는 즉시 acknowledge (3일 내 미확인 시 Google 자동 환불 → 유저가 돈 내고 구독을 잃는 사고 방지).
  acknowledge 실패해도 PRO는 준다(돈 낸 사람을 막지 않음).
- 구매 토큰을 저장하고 **유니크 인덱스**로 한 계정에만 묶는다 → 영수증 공유 차단(`already_claimed`).
- **갱신·해지는 Pub/Sub(RTDN) 없이** `/v1/me`에서 따라잡는다: 저장된 만료 시각이 지났을 때만 Google에 다시 묻는다.
  갱신되면 다음 앱 실행에 PRO 복구, 해지되면 같은 시점에 free. RTDN 설정(Pub/Sub 토픽·권한)을 기획자 To-Do에서 덜어냄.
- Play가 응답하지 않으면 `unavailable` → **기존 PRO를 건드리지 않는다**(Play 장애로 결제한 유저의 PRO를 끄면 안 됨).
- 서비스 계정 JWT → OAuth 토큰 교환은 google-auth 의존성 없이 PyJWT로 직접 구현(스코프 1개, 엔드포인트 1개).

**광고 (AdMob SDK)**
- `ServerSideVerificationOptions.userId = Supabase user id`. 적립은 기존 SSV 콜백(서명 검증 + transaction_id 멱등)이 하므로
  클라이언트는 여전히 스스로 충전할 수 없다.
- 기본 광고 ID를 **Google 공식 테스트 ID**로 두어 AdMob 계정 없이도 앱이 뜨고 광고 화면까지 확인 가능.
  단 테스트 광고는 SSV 콜백을 보내지 않으므로 실제 충전은 실제 ID 필요(human-todo A5).

### 12.3 교정 품질 — 사전 130 → 193
실사용 빈도가 높은데 빠져 있던 오타를 63개 추가(`-예요`, 폭팔, 치뤘, 만듬, 촛점, 떡볶기, 육계장, 곱빼기, `-쟁이`,
`-컨대`, 귀띔, 무릅쓰다, 안절부절못하다 등).

**오탐 원칙을 명시적으로 고정했다.** 문맥에 따라 맞고 틀림이 갈리는 표현은 확실한 연어만 규칙화한다:
- `찌게` 단독 금지 — "살이 **찌게** 되다"가 올바른 문장이다 → `김치찌게`·`된장찌게` 등 합성어만 등록
- `낳으` 단독 금지 — "아이를 **낳으**세요"가 올바른 문장이다 → `빨리 낳으`·`감기 낳`·`병이 낳` 연어만 등록
- `치루`는 의학 용어(痔瘻)와 충돌 → `치뤄`·`치뤘`·`치룬`·`치룰` 활용형만 등록

이 경계를 지키는지 검사하기 위해 골든 파일에 **`clean_cases`(올바른 문장 → 교정 0건)** 섹션을 신설하고
backend·Android 양쪽 테스트에 연결했다. 규칙을 넓히다 오탐이 생기면 3 플랫폼에서 동시에 실패한다.

### 12.5 계측 (기획자 결정: Firebase Analytics)
중단/피벗 기준을 세워 놓고 측정 수단이 0줄이던 문제를 해결했다.

- 이벤트 카탈로그를 **keyboard 모듈에 Firebase 의존 없이** 정의(`analytics/Analytics.kt`). 호스트 앱이
  `TypeRightApplication`에서 sink를 주입하고, IME는 `services.analytics`로만 보고한다. 같은 프로세스라 키보드 단독
  실행에서도 동작한다.
- 수집 이벤트 16종: `keyboard_shown`(기본 키보드 유지율의 단위), `ime_status`, `rules_found`, `ai_checked`,
  `correction_applied`, `correction_ignored`, `feedback_shown`, `mode_changed`, `quota_exhausted`,
  `process_text_opened`, `share_card_created/shared`, `reward_ad_watched`, `purchase_started/verified`, `signed_in`.
  사용자 속성 3종(plan / signed_in / feedback_mode)으로 리텐션을 세그먼트별로 쪼갠다.
- **입력 텍스트는 절대 보내지 않는다.** 교정 단어도, 타이핑 중인 앱의 패키지명도 보내지 않는다(앱은
  messenger/social/work/browser/other 5개 버킷으로만). 파라미터는 숫자·enum·불리언뿐이며,
  `AnalyticsEventTest`의 "no event carries free text"가 허용 문자열 화이트리스트로 이를 강제한다.
  키보드 앱에서 이 선이 무너지면 제품 전체가 끝나므로 테스트로 못 박았다.
- `correction_ignored`가 늘면 = 규칙 오탐이 늘었다는 뜻. 12.3의 `clean_cases`와 짝을 이루는 사후 지표다.
- `google-services.json`이 없으면 Gradle 플러그인 자체를 적용하지 않아 **빌드가 깨지지 않고**, sink는
  `Analytics.None`으로 떨어진다. 사람이 파일 하나만 넣으면 그 순간부터 수집이 시작된다(human-todo A9).

## 13. 에뮬레이터 설치 확인 (2026-09-21)

맥북 에뮬레이터(AVD `fearless_test`, Pixel 6 / Android 15 / arm64, `emulator-5554`)에서 사람이 직접 눌러 볼 수

  `:app:assembleDebug`가 그대로 성공했다. 12.5에서 의도한 "google-services.json 없으면 플러그인 미적용" 경로와

- JDK: 시스템 java_home에 OpenJDK 25만 있어 AGP가 거부한다. Android Studio 번들 JBR 21로 빌드했다
  (`JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew :app:assembleDebug`).
- `SUPABASE_URL`이 비어 있어 호스트 앱이 **개발 모드 인증**(`X-Dev-User-Id`)으로 뜬다 → 구글 로그인 없이
  온보딩 3단계를 통과할 수 있다. 실기기 구글 로그인 확인은 human-todo A 항목이 끝나야 가능.

  (`shareable`는 규칙 엔진 피드백에도 붙는다), 이모지 패널, 롱프레스 숫자, 진동·소리, 보안 키패드,
  텍스트 선택 메뉴 [맛춤뻡 검사].
- 백엔드 필요: AI 문맥 교정·쿼터·충전·PRO. 네트워크 실패는 무음 폴백이라 규칙 칩은 그대로 남는다
  (에뮬레이터에서 로컬 백엔드는 `http://10.0.2.2:8790`).
- 이 결과를 반영해 [human-todo.md](human-todo.md) D절을 재구성했다. 항목마다 🟢(지금 에뮬레이터로 가능) /
  🟡(일부만, 최종 판단은 실기기) / 🔴(실기기·A항목 필수)를 매기고, 에뮬레이터로 지금 확인 가능한 항목
  D11~D16(온보딩, 규칙 교정, 3모드 문구, 보안 키패드, 오탐 수집, 진동·소리)을 신설했다. 각 행에 사람이 채울
  '확인 결과' 칸을 비워 두었다. E절 순서도 "🟢 항목은 계정 작업을 기다리지 말고 먼저"로 고쳤다.

## 14. 기획자 확정: 온디바이스 전용 선출시 (2026-09-21)

2. 지금 출시를 막는 것이 **전부 계정·키 작업**이다(OpenAI 키, Vercel, Supabase, OAuth, 구독 상품,
   영수증 검증 서비스 계정, AdMob). 기능이 부족해서가 아니다.
3. AI 교정은 **쓸수록 비용이 나가는데 사용자가 0명**이다. 리텐션이 확인되기 전에 변동비를 켤 이유가 없다.

이 결정은 10절(로그인 1종·PRO·광고)과 11절의 수익 설계를 **폐기하는 것이 아니라 뒤로 미루는 것**이다.
10.6이 이미 "로그인 강제 없음, 온디바이스로 즉시 사용"을 확정해 둔 덕분에 온디바이스 경로가 이미 기본 경로였고,
그래서 이번 변경이 기능 삭제가 아니라 진입점 차단으로 끝났다.

### 14.2 비활성화 방식 — flavor 한 축
`BuildConfig.CLOUD_FEATURES` 하나를
[FeatureFlags.kt](../android/keyboard/src/main/java/com/typeright/keyboard/FeatureFlags.kt)가 받아
`ai / auth / billing / ads / shortcutSync / proGate`로 나눠 준다. 그 값은 **product flavor**가 정한다
(`features` dimension, :app 과 :keyboard 공통):

| flavor | `CLOUD_FEATURES` | 빌드 |
|---|---|---|
| `ondevice` (기본, 출시 형태) | `false` | `./gradlew :app:assembleOndeviceDebug` · `:app:bundleOndeviceRelease` |
| `cloud` | `true` | `./gradlew :app:assembleCloudDebug` |

처음에는 Gradle 속성 한 개로 했다가 flavor 로 바꿨다. 속성으로는 **소스셋과 매니페스트를 가를 수 없어서**
AdMob SDK 와 `com.google.android.gms.ads.APPLICATION_ID` 메타데이터가 출시 AAB 에 그대로 남기 때문이다(14.7). **서버 코드·Supabase 마이그레이션·Play 결제 코드·테스트는 하나도 지우지 않았다.**
백엔드는 배포만 안 할 뿐 그대로 있고, `AiCallPolicy`·`ShortcutAccess` 같은 순수 로직은 손대지 않아
단위 테스트도 그대로 남아 있다(차단은 전부 호출부에서 한다).

`FeatureFlagsTest`가 "플래그를 되살릴 때 일부만 켜지는 사고"를 막는다 — 어느 값으로 빌드하든
여섯 스위치가 같은 값이어야 하고, PRO 구독자는 어떤 빌드에서도 잠기지 않아야 한다.

### 14.3 "막다른 길을 남기지 않는다" — 실제로 고친 것
기능을 끄면 **없는 기능을 가리키는 잔상**이 남는다. 화면을 직접 눌러 보며 찾아낸 것들:

| 잔상 | 처리 |
|---|---|
| PRO 탭 — 살 수 없는 상품만 있는 화면 | 탭 자체를 뺀다 (3탭) |
| 온보딩 3단계 로그인 · 4단계 AI 훈수 | 카드 제거 → 1·2단계와 테스트 입력만 남는다 |
| 설정의 계정·AI 카드, ⚡충전 | 제거 |
| 키보드 제안 바 "🔑 로그인하면 AI 훈수" 칩 | 제거 |
| 제안 바의 "AI 꺼짐" 배지가 **영구 표시** | AI가 없는 빌드에서는 상태 표시를 비운다 |
| 경찰 모드가 아예 선택 불가 (`allowPolice = signedIn`) | 로그인이 없는 빌드에서는 바로 선택 가능. 동작은 진동 경고까지 |
| 설정의 경찰 모드 설명이 **없는 PRO 차단을 광고** | 이 빌드에서 실제로 되는 동작으로 문구 교체 |
| 커스텀 단축어가 PRO 잠금 → **아무도 못 여는 상태** | 기기 안에서 열어 준다(동기화만 빠짐). 14.4 참고 |
| [맛춤뻡 검사]의 "AI 훈수도 받아보기 →"·충전 | 규칙 결과만 보여주고 끝낸다 |
| 온보딩 개인정보 문구 "AI 훈수는 동의 시 서버로 보내요" | "전부 기기 안에서 해요. 서버로 보내지 않고 로그인도 필요 없어요"로 교체 |
| 온보딩 부제 "AI 키보드를 설정해요" | AI가 없는 빌드에서는 "AI"를 뺀다 |
| 옛 딥링크 `typeright://reward` 가 살아 있음 | 빈 팝업 대신 즉시 닫는다 (AdMob SDK 초기화도 여기서 막힌다) |

### 14.4 판단이 필요했던 두 가지 (기획자 확인 요망)
- **커스텀 단축어**: 10.1에서 "무료는 기본 3개, 추가는 PRO"로 확정했는데, 결제가 없는 빌드에서 이 잠금을 그대로
  두면 **아무도 열 수 없는 페이월**만 남는다. "막다른 길 금지" 지시에 따라 이번 빌드에서는 기기 안에서 무료로
  열어 두었다(`FeatureFlags.proUnlocked`). 결제를 되살리면 원래 페이월이 자동으로 돌아온다.
  → 그대로 둘지, 아니면 단축어 탭을 통째로 숨길지 확인 필요.
- **경찰 모드 입력 차단**: 원래 PRO 기능이라 이번 빌드에는 없다. 모드 자체는 되고 진동 경고까지 동작한다
  (= 기존 무료 플랜 동작 그대로). 단축어와 달리 막다른 길이 아니라서 잠긴 채로 두었다.

### 14.5 Firebase 계측 — 남기기를 권함 (개발 판단)
코드는 그대로 두고 플래그로 끄지 않았다. 근거: `google-services.json`이 없으면 이미 no-op이고,
**이번 결정으로 계측의 가치가 오히려 커졌다** — AI·결제를 뺀 이번 출시의 유일한 질문이
"사람들이 이걸 기본 키보드로 계속 쓰는가"(11.1의 기본 키보드 유지율 + D7/D30)이고, 그 답을 주는 것이 계측뿐이다.
12.5대로 **출시 전에** 켜 놓지 않으면 첫 주 데이터를 영영 못 본다. 비용·계정 결제도 없다(파일 하나).
다만 켜면 B2-1(데이터 보안 양식에 '앱 활동 분석' 추가)이 따라온다. 안 넣으면 계측이 꺼진 채로 나갈 뿐 출시는 된다.

### 14.6 검증
- `:app:assembleDebug` — 플래그 **off/on 양쪽 다** 빌드 성공(되살리기 경로가 깨지지 않았는지 확인)
- `:keyboard:testDebugUnitTest` — **169개 통과 / 실패 0** (기존 166 + `FeatureFlagsTest` 3). 기존 테스트는 수정 없음
- 에뮬레이터(`emulator-5554`) 설치 후 화면 확인 — 앱을 force-stop 후 새로 띄워 전 항목 재확인:
  3탭(PRO 없음), 온보딩 1·2단계 + 테스트 입력만, 개인정보 문구가 "전부 기기 안에서"로 교체됨,
  단축어 추가 다이얼로그가 페이월 없이 열림, 설정에 계정·AI 카드 없음,
  경찰 모드가 **로그인 팝업 없이 바로 선택**되고 설명에 PRO 언급이 사라짐
- 같은 날 다른 세션이 에뮬레이터를 순서 없이 조작해 이 앱 화면에 탭이 흘러든 사고가 있었으나,
  키보드 활성화 상태·앱 설정값 모두 변경 없음을 확인했다(IME 미활성, 기본값 유지). 이후 재확인은 전부
  조작 전 포그라운드를 확인하고 진행했다

### 14.7 기획자 답변 반영 (2026-09-21) — SDK 분리·서명·계측

| 항목 | 결정 | 반영 |
|---|---|---|
| 커스텀 단축어 | **이번 출시에 무료로 연다** | 10.1의 "추가는 PRO 전용"은 **이번 출시에 한해 예외**다. 결제를 되살리면(`cloud` flavor) 원래 페이월이 자동 복구된다 |
| 경찰 모드 입력 차단 | **잠근 채로 둔다** | 모드는 되고 진동 경고까지. 개발 기본안 유지 |
| Firebase 계측 | **넣는다** | 코드는 이미 준비됨(12.5). 사람이 `google-services.json`만 넣으면 됨 → human-todo [이번] 항목으로 승격 |
| AdMob SDK | **뺀다** | 아래 참고 |
| Play Billing SDK | **같이 뺀다** (개발 판단) | 아래 참고 |

**AdMob·Play Billing을 APK에서 완전히 제거했다.** 플래그만으로는 부족했다 — Gradle 속성은 코드 분기만 바꿀 뿐
의존성과 매니페스트는 그대로라, 광고를 싣지도 않는 앱에 **Google 테스트 AdMob 앱 ID**가 박힌 채로
프로덕션 AAB가 나간다. 그래서 `features` dimension의 product flavor로 바꿔 소스셋·매니페스트·의존성을 함께 갈랐다.

- `app/src/cloud/` — `ads/`, `billing/`, `reward/`, `ui/SubscriptionScreen.kt` + `AndroidManifest.xml`
  (AdMob 메타데이터, `RewardAdActivity` 선언)
- `app/src/ondevice/` — `SubscriptionScreenStub.kt` 하나뿐. `TypeRightApp`의 탭 분기가 이름으로 참조해서
  자리 채움이 필요하다(PRO 탭이 걸러지므로 **실행되지는 않는다**)
- `cloudImplementation(libs.play.billing)` / `cloudImplementation(libs.play.services.ads)`
- `RechargeButton`이 `RewardAdActivity`를 **클래스로** 참조하던 것을 딥링크(`typeright://reward`)로 바꿨다.
  덕분에 스텁이 하나로 줄었다 (키보드·[맛춤뻡 검사]도 원래 딥링크를 쓴다)

Play Billing도 같이 뺀 이유: 남겨 두면 Play Console에 인앱 상품을 신고해야 하는데 **살 수 있는 상품이 없고**,
구매 경로가 없는 앱에 결제 SDK가 들어 있으면 심사에서 설명할 거리만 된다. 스텁 하나로 끝나서 비용도 낮았다.

검증 (APK dex 실측):

| | `ondevice` | `cloud` |
|---|---|---|
| APK 크기 (debug) | 16MB | 19MB |
| `gms/ads` 참조 | **12** (전부 `gms/ads/identifier`) | 1409 |
| `billingclient` 참조 | **0** | 13 |
| `RewardAdActivity` | **0** | 16 |
| 매니페스트의 AdMob·보상광고 항목 | **0** | 2 |

`ondevice`에 남은 12개는 전부 `gms/ads/identifier`(광고 ID 조회)로, **AdMob이 아니라 Firebase Analytics**가
끌고 오는 것이다. 광고를 싣지 않는 앱이므로 매니페스트에 `google_analytics_adid_collection_enabled=false`를
넣어 수집 자체를 껐다 — Play '데이터 보안'에서 광고 ID 수집을 신고하지 않아도 되고, 측정하려던
기본 키보드 유지율·리텐션은 광고 ID 없이도 그대로 나온다.

**릴리스 서명**: `android/keystore.properties`(gitignore)가 있으면 서명하고, 없으면 **서명 없이** 빌드한다.
디버그 키로 폴백하지 않는다 — 디버그 키로 서명된 AAB를 Play에 올리면 업로드 키가 그대로 굳어 버린다.
양식은 [keystore.properties.example](../android/keystore.properties.example). 키스토어 생성·보관은 사람 작업이다.

**`.gitignore` 보강**: `google-services.json`, `*.jks`, `*.keystore`, `keystore.properties`가
무시 목록에 없었다. 사람이 파일을 놓는 순간 커밋될 수 있는 상태였어서 먼저 막았다.

검증: `ondevice`·`cloud` 양쪽 **169개 통과 / 실패 0**, `:app:bundleOndeviceRelease` 성공(서명 없음 = 의도대로).

### 14.8 개인정보처리방침 · 출시 마감 작업 (2026-09-21)

**방침 페이지를 저장소 안에 만들고 설정 화면에서 연다.** 지금까지 방침 URL 상수는 AI 동의 팝업에서만 쓰여
이번 빌드에서는 화면에 아예 나오지 않았다. 키보드는 Play가 입력 데이터 취급을 특히 깐깐히 보고(B3)
사용자도 가장 의심하는 종류의 앱이라, 링크를 눈에 보이는 곳에 두는 편이 낫다.

- `site/privacy/index.html` — 방침 본문. `site/index.html` — 한 줄짜리 진입 페이지.
- `.github/workflows/pages.yml` — **`site/`만** 배포한다. 기본 방식인 `/docs` 배포를 쓰지 않은 이유는
  이 레포의 `docs/`가 기획 로그·수익 추정·사람 할 일 같은 내부 메모이기 때문이다. 레포가 public이라 파일
  자체는 이미 보이지만, 웹사이트로 렌더링해 검색에 노출시킬 이유는 없다.
- 설정 탭 맨 아래 '정보' 카드: 개인정보처리방침 · 오픈소스 라이선스 · 버전.
  라이선스는 온디바이스 빌드에 실제로 들어 있는 구성요소만 적었다(전부 Apache-2.0).
- `Links.PRIVACY_POLICY_URL` → `https://pppclove29-bit.github.io/SpellCheck-Board/privacy/`
  (자리표시였던 `typeright.notion.site` 교체). Pages 공개 설정은 사람 작업 — human-todo B1-2.

**방침 문구는 코드와 한 줄씩 대조해서 썼다.** 공개 문서라 실제 동작과 어긋나면 안 되기 때문이다.
대조표는 [privacy-claims.md](privacy-claims.md)에 **상시 문서로** 남겼다 — 아래 표는 작성 시점 기록이고,
앞으로 코드를 바꿀 때 참조해야 하는 것은 그쪽이다(어느 코드를 건드리면 어느 문장이 깨지는지까지 적어 두었다):

| 문구 | 근거 |
|---|---|
| 입력한 문장을 전송·저장하지 않음 | ondevice 빌드에 텍스트가 나가는 경로가 없다(AI 호출은 `FeatureFlags.ai`에서 차단) |
| 보안 입력란에서는 **검사 자체를 안 함** | `runLocalCheck()`이 `ui.secure`면 즉시 반환 — 규칙 엔진이 텍스트를 읽지도 않는다 |
| 클립보드를 읽지 않음 | `setPrimaryClip`(쓰기)만 있고 `getPrimaryClip`은 코드에 없다 |
| 계정·로그인 없음 | `FeatureFlags.auth = false` |
| 앱 삭제 시 함께 삭제 | `allowBackup="false"` |
| 통계에 입력 글자·앱 이름 없음 | `AnalyticsEventTest`가 자유 텍스트를 금지, 앱은 5개 버킷으로만 |
| 광고 ID 미수집 | `google_analytics_adid_collection_enabled=false` (14.7) |

초안에 있던 "기능 사용 횟수뿐"은 **부정확해서 고쳤다.** Firebase는 앱 버전·기기 모델·OS 버전·IP 기반
대략적 지역·설치별 익명 식별자를 자동으로 수집한다. 방침에 그대로 적었다.

**출시 마감 작업**
- `versionName` `0.1.0` → **`1.0.0`**, `versionCode` 1 유지.
- **아이콘은 지금 것으로 낼 수 있다.** 기본 안드로이드 아이콘이 아니라 파란 배경 + 흰 키보드 + 체크로 된
  어댑티브 아이콘이고, 전경이 안전영역(중앙 66dp) 안에 들어온다. Android 13+ 테마 아이콘용
  `<monochrome>` 도안만 빠져 있어 추가했다(없으면 시스템이 전경을 단색화하면서 흰 본체에 체크가 파묻힌다).
  Play 스토어 등록용 512×512 PNG는 APK와 별개로 콘솔에 올려야 하므로 사람 작업으로 남는다.
- **R8(minify)은 끈 채로 첫 출시를 낸다.** 키보드는 잘못 축소되면 사용자가 글자를 못 치는 상태가 되는데,
  릴리스 키스토어가 아직 없어 축소된 릴리스 빌드를 실기기에서 검증할 방법이 없다. 첫 출시의 목적은
  리텐션 측정이지 용량 절감이 아니다. 키스토어가 생기고 실기기로 한 번 훑은 뒤 켠다(human-todo C6).
